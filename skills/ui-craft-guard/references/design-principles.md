# 可执行的 UI 审美判据（Rulebook）

规则类型：`FLOOR` 为可用性底线、`CONTEXT` 为需要场景判断、`HEURISTIC` 为高频 AI 模板线索、`POLISH` 为像素与状态级精修。每条必须指出位置、证据与例外；单独命中 HEURISTIC **不能证明设计差**。

| ID | 规则 | 如何观察 / 修复 | 不应套用的情形 | 来源 |
|---|---|---|---|---|
| G01 | 单个界面有一个清晰主任务 | 首屏主动作、信息层级和下一步可被迅速识别；减少无谓的选择点 | 探索性内容目录需并列入口 | Xian、Zayn |
| G02 | 视觉语言与产品匹配 | 审核行业、受众、素材、品牌是否支持特定配色/材质 | 不因“去 AI 味”剥离品牌识别 | Xian |
| G03 | 先归因再改 | 先给问题位置、原因、规则、验证方式；改一组、复查 | 紧急可靠性修复优先 | Xian；本仓库工作流 |
| C01 | 界面 chrome 颜色克制，内容可突出 | 统计竞争性强调色、CTA 层级、照片饱和度；减少随机卡片上色 | 儿童产品、医疗警示、品牌活动页有正当多色 | ianneo_ai |
| C02 | 色彩采用语义 token | 背景/前景/边框/交互态有角色和对比度；可参考 Radix 色阶 | 现有成熟设计系统不可全量替换 | Zayn；Radix |
| C03 | 避免惯性紫蓝渐变和渐变字 | 找出使用渐变的任务理由；无必要则简化 | 品牌既定或有真实视觉叙事支持 | dingyi；Xian |
| T01 | 控制字号层级 | 审核一屏字体角色是否过度碎片化；建议先设 3–4 个角色 | 数据密集界面允许明确定义更多角色 | Zayn |
| T02 | 不能靠过小文字换“精致” | 正文/帮助信息实际测试可读性；12px 是部分作者的建议下限，非 WCAG 通用规则 | 合理的代码/徽章密度可调整，但需测试 | Zayn；本仓库校准 |
| T03 | 中文、中英混排真实验收 | 实机检查字重、fallback、行高、字距、数字与中文相邻 | 非中文界面不强加字体栈 | RicoUI |
| T04 | 文案以用户任务为准 | 删除无信息价值的夸张口语、重复描述、虚构数据 | 必须保留输入格式、风险说明、错误反馈 | Zayn；dingyi |
| G04 | 嵌套圆角几何一致 | 若内外都是实色同心矩形，内半径近似 `max(0, 外半径 - 内边距)`，按渲染核对 | 不同内边距、边框、非同心、透明内层不机械计算 | Kubai；Zayn |
| G05 | 限定 radius/shadow 家族 | 定义少量语义值，避免每张卡片完全不同弧度和多层装饰 | 有意的品牌插画或拟物材质例外 | Kubai；dingyi |
| G06 | 细线由显示环境决定 | 比较 0.5px、1px 在目标设备上的清晰度和可触达反馈 | 低 DPI、缩放、可访问性边界不能强制 0.5 | Zayn；本仓库校准 |
| G07 | 对齐包含视觉重心 | 比较文字基线、图标中心、边缘和光学错觉，必要时补偿 | 不为像素齐整破坏响应式内容流 | Zayn |
| I01 | 交互不平白增加判断 | 核对用户是在执行主任务时自然选择，还是被模糊选项打断 | 专业模式确实需要多分支 | Zayn |
| I02 | 反馈状态不可省略 | 有 hover/focus/pressed、禁用、加载、错误、成功，表单失败保留输入 | 无需假装有未实现的服务器行为 | 本仓库；WCAG |
| M01 | 动效要表达空间关系或状态 | 只保留能帮助追踪焦点与内容变化的动效；250ms 可作起点 | 系统减少动态效果偏好应优先 | Zayn；Kubai（系列） |
| M02 | 图标随背景/主题测试 | 在浅/深/透明背景确认对比、层次与识别；不要只做缩小大图 | 项目没有多主题时无需臆造图标变体 | remixdesigner 案例启发（C 级） |
| S01 | 模板痕迹须有证据 | emoji 图标、平均三卡片、居中大字、眉标、彩色左边线都要解释其作用 | 这些元素在真实品牌语言中可能合理 | dingyi；Xian |
| F01 | 对比度和键盘可用优先 | 一般文本 >= 4.5:1；大字 >=3:1（WCAG AA 例外另详见规范）；可用焦点 | 不可用“审美克制”取消焦点 | WCAG 2.2 |
| F02 | 响应式和异常数据不塌 | 320/375/768/1280+，长中文、空态、错误态、长数字、放大字号 | 具体断点由产品决定 | 本仓库验证流程 |
| F03 | 不捏造信任信号 | 虚构统计、客户好评、奖项和假机构名均拦截 | 真实有据可验证时可以使用 | Xian 案例；本仓库安全约束 |

推荐的优先顺序：功能/安全 → 行为 → 内容结构 → 视觉层级 → 品牌个性 → 间距/圆角/阴影 → 动效。在每一轮只改动可以用截图、代码 diff 或用户任务测试证明的东西。
