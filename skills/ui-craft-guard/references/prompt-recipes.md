# 可复用的任务提示词（原创）

## 仅审计

> 用 ui-craft-guard 的 audit 模式检查当前页面。先识别产品主任务与原有品牌边界；给出带规则 ID、代码/截图位置、具体证据、影响、风险和验证方式的优先级报告。不要修改文件。把审美偏好与真正的可用性缺陷分开。

## 修改已有 UI

> 用 ui-craft-guard 审查并优化这个界面。第一轮先列出严重问题和应保留的有效设计，不改业务逻辑；第二轮按 FLOOR→STRUCTURE→TASTE→POLISH 小步修改，保留 diff。不要把页面统一改成黑白灰，不强制 0.5px 边框。所有调整必须说明理由，并以同视口截图和键盘/表单测试验收；工具无法运行就列未测项。

## 中文内容页

> 以中文读者的阅读节奏优化当前内容页。优先检查 28 字标题断行、中英文/数字混排、中文字体回退、字重、行高、首屏信息层级及 320px 手机宽度。不要新增无意义的英文眉标、 emoji 图标或假数据。给出前后差异与实际验证。

## 设计新界面

> 在写组件前写一页 Design Read：目标用户、唯一主任务、页面内容优先级、品牌个性、参考作品的可借鉴原理、明确拒绝的模板模式。提供 2–3 个真正不同的设计方向及其 trade-off，然后使用明确的 token 实现其中与任务最匹配的方向，完成响应式和异常状态测试。

## 前后对比

> 保持相同内容与视口比较两版 UI。指出至少 3 个观察到的具体差异，包括改进与退步；为每个差异绑定 rule ID 和验证方法。没有渲染证据时不要声称实际视觉改善。
