# 设计意图协议：不把去 AI 味变成新的统一模板

设计个性不是“多用独特颜色”，也不是给每个网站强造签名元素。要判断的是：这个产品为什么这样表达，它传达给谁，是否帮助用户完成真实任务。

## 必须建立的 Design Intent Brief（简短但独立）

1. **用户与目标**：谁在什么场景完成哪件事；是否有高频任务或阅读任务。
2. **产品定位**：明确的品牌声明、设计原则、目标市场、语调、内容类型；注明来自用户/品牌文档还是推断。
3. **视觉现状**：字体角色、配色、密度、材质、留白、图像、动效、组件行为，分别列出观察证据。
4. **意图假设**：例如“冷色和稀疏信息用于建立可信、宁静的理财感”，不把主观联想当事实。
5. **反面解释**：这一选择也可能是默认组件/未经思考/移动端退化，哪些证据能区分？
6. **保留条件与改变条件**：什么情况下保留，什么真实观察会推翻原假设？

项目没有正式品牌指南时，不要强迫用户提供；先阅读现有产品、内容与代码，再把推断列为 provisional。关键前提无法判断时只问会改变结论的最小问题。

## 区分定位契合度与审美口味

- **风格是否罕见** ≠ 设计个性强。奇怪的排版可能降低理解效率。
- **风格是否常见** ≠ 设计个性弱。一个工具型后台坚持高度稳定的规范也可能正是差异化选择。
- **渐变、卡片、居中 Hero、衬线字体** ≠ 自动禁用项。先研究其语义、品牌资产、媒体内容和用户场景。
- **个性存在的主要证据**：关键视觉选择能解释产品的受众、内容或使用节奏；多页之间有明确的视觉语法，而非随机装饰。

## 反证审查（必须做）

每条关于设计个性的 change/retain/investigate 判断至少回答：

- 我观察到的究竟是什么？是否有页面、品牌或任务证据？
- 最强的合理替代解释是什么？例如“品牌本来就采用这套紫色渐变”。
- 如果不改，会有什么可以观察到的损失？如果改，可能破坏什么？
- 什么新证据能让我改变当前判断？

**默认没有义务修改**。允许输出“当前设计合理，保留”“尚不知道，需要验证”“视觉确有偏差，建议调整”三类结论。设计个性不要单项打分，不强行把美学偏好量化。

## 三个验收反例

**品牌渐变页**：有真实品牌规范将渐变列为核心识别；实际对比与可用性没有问题。结论应是 retain，而不是无条件消除紫色。

**朴素高效后台**：面向高频操作员工，功能密度和简约性提升任务效率。不要为了制造“特色”增加插画、渐变、大卡片。结论可以 retain。

**精致但表单提交失败**：高清截图美观不能抵消任务失败。应将 usability + FLOOR 作为 P0，实测复现后 change；设计个性不必被牵连。

对应可机读合约及反例：`examples/audit-cases/` 和 `tests/test_report_contract.py`。这些测试验证**结论的证据结构**，不是声称测试程序本身拥有设计审美。
