# 教学案例：一个阅读工作台的前后对比

> 两份示例 HTML 均为本项目原创。`anti-pattern.html` 故意制造静态信号；`revised.html` 采用更有任务关系的内容结构。此案例不声称运行了浏览器视觉测试或真实用户研究。

## 用户任务

用户快速保存文章标题、浏览已有阅读清单。设计应该先让阅读清单可辨认，再让“添加标题”动作容易操作，而非展示“未来感”。

## 初版主要问题

- `H01/H02`：无业务理由的紫色渐变和渐变字；内容尚未展示，装饰已占据注意。
- `G04`：外/内卡片均为 24px 圆角，同时内层 padding 16px；建议以同心关系重新核对，但不是脚本可证实的缺陷。
- `T01/T02`：字号选择分散且含 10/11px；真实中文手机环境可读性存疑。
- `A01/A03`：空目标链接、无替代焦点样式，是比美观更优先的风险。
- `H04/H05`：卡片左侧彩线与全属性 800ms 过渡缺乏信息功能。
- `G01/T04`：泛化口号无法解释任务，3 张卡片没有实际操作。

## 修订决策

- 围绕“待阅读/加入收藏”组织，不机械三等分；
- 白色输入面板与页面分层，焦点可见；
- 使内外半径几何更合理（外20、padding12、内8）并控制字号角色；
- 在表单提交后加入真实的前端列表反馈，明确它不会跨刷新保存（未连接后端）；
- 320–1440px 的适配由 CSS 实现，且已通过 Chromium 375、768、1280px 冒烟测试，但不等于全设备兼容性已验证。

## 复现静态检查

```bash
python3 scripts/audit_ui.py examples/anti-pattern.html
python3 scripts/audit_ui.py examples/revised.html
python3 -m unittest discover -s tests -v
```
