# 真实网站端到端盲测协议（模板，尚未执行）

**状态：NOT_EXECUTED。** 这是下一次真实项目评估的可复核执行规范，**不是**一次已经完成的案例，也不包含任何真实用户研究或通过数据。仓库的 [原创页面演练](workflow-walkthrough.md) 是教学材料，不可充当真实网站盲测。

## 为什么要测

代码和 JSON 合约测试可以证明部分约束被遵守，却无法证明 Skill 的设计判断真的有效。真实网站评估至少应分别检验：

- **发现能力**：是否自主发现重要但初始需求未指出的问题？是否遗漏严重任务故障？
- **判断能力**：结论是否有可复查证据、合理反证，是否错误地建议移除品牌或有效设计？
- **验证能力**：经授权的修改是否让同一任务或界面更好，是否引入新退化？

**不能仅用“建议数量”“感觉更漂亮”“扫描器 0 告警”代替这些结果。**

## 执行门槛与材料

- [ ] 获得网站所有者或有权管理者的审计许可；确认是否允许访问测试账号、修改源码、保存截图。
- [ ] 不向公开仓库提交密码、会话、客户数据、私人截图或未经授权素材；必要时脱敏。
- [ ] 固定基线：站点/部署版本、关键页面、目标任务、浏览器、视口、日期与明确的不可更改约束。
- [ ] 先封存基线及初始需求，使第一轮审计者**不知道预先人工列出的缺陷清单**；后续再比对遗漏与误报。
- [ ] 给 Skill 与普通项目开发者同样可用的产品资料；不得在提示词里暗示答案。
- [ ] 准备可复查的 Evidence 文件、任务步骤和已知问题核对办法。

## 四阶段执行，保留审批边界

1. **盲审（audit）**：使用 [阶段 ① 话术](../skills/ui-craft-guard/references/prompt-recipes.md)，限定访问范围，输出四层覆盖、三维独立结论、`finding_id/rule_id`、证据/反证、change/retain/investigate 和未测事项。此时不修改文件。
2. **设计决策（audit 后续分析）**：按已有发现归并根因与共享组件问题；最强反证挑战“需要改”的判断。负责人确认哪些建议允许进入修改。
3. **受控修改（redesign）**：只实施获批内容，保留 commit、截图和回归记录。不影响未获授权页面、数据和第三方资产。
4. **比较与外部复核（compare）**：同内容、同视口、同浏览器、同任务重放；比较改善/持平/退化/未知。最好由未参与原修改的另一审查者独立评分和复核；同一 Agent 自评只写“批判性自检”。

## 评估口径

- 有效发现率可以记录为“已复核的重要发现 / Skill 提出的重要发现”，但必须同时列出漏报；分母很小时不伪装成稳定概率。
- 任务完成率、时长、错误率等只有在**确实设计并执行了可比任务测试**后才能报告；不能由静态截图推算。
- 视觉和品牌判断必须保留评审者差异与最强反对意见，不用无依据总分。
- 需要跨站点或跨行业比较时，应覆盖不同类型（内容编辑、消费品牌、后台工具），而非仅选适合 Skill 偏好的页面。
- 将失败、改变判断的证据、误报与撤回决定也保留在结果中；成功案例不是唯一可发表结果。

**交付验收**：只有存在真实的许可、输入、审计报告、变更记录、前后证据与独立复核信息，才能把本文件复制为一份“真实网站测试结果”。在此之前状态保持 NOT_EXECUTED。
